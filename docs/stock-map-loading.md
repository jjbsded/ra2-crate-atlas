# 官方地图加载边界

本轮补齐原先剩余的 10 份官方地图文件。结论针对内置 RA2 1.006 / YR 1.001
资源与文件初始状态，不推进触发器、单位任务或矿石生长。源地图字节不改写。

## 自定义地图的版本选择

`map-import-version.js` 将用户选择的资源策略与上一次地图显示的版本分开保存。打开原版官方地图只更新显示版本，不把后续导入永久切成原版。自动模式下，`.yrm` 使用尤复提示、`.mpr` 使用原版提示；`.map` 后缀不能区分引擎，默认尤复。已配置的游戏目录在完整版自动模式中仍优先，用户显式选择的资源版本继续生效。Toy 与完整版共用导入流程，不再在构建时注入另一份上传逻辑。

按错误的原版资源读取尤复 CAMACH 时，内置建筑 art 缺失会令分析退入近似模型。这不表示尤复素材缺失，也不表示该地图没有禁行格。当前近似分析仍预测可读格子的禁行风险，不再按整图隐藏。回归样本 `SAVE7680_AB.yrm` 在尤复资源下完整分析得到 38 个当前禁行格、0 个清空后潜在禁行格。`verify-map-import-version.cjs`／`verify-resource-ui.cjs` 检查选择优先级，`verify-map-import-version-ui.cjs` 在 Full／Toy 实际执行“打开原版官方图 → 导入 YRM → 检查精确分析与禁行列表”；输入地图仅只读。

## 错误隔离与功能恢复

告警和近似状态不再作为整图功能锁。完整版（包括本地游戏目录）与 Toy 都按可读数据继续运行概率、Buff 期望、模拟放置、区域统计、导出及 3D；不可计算的局部保留告警，不把未知结果当作零。

- 只有单位贴图缺失时，保留已知的单格占用；未知建筑仍按可读基础或原点降级，不猜测完整占地。
- 近似报告用 `metadata.riskPredictionVersion=1` 表明已进行局部禁行预测。`riskKnown=false` 表示当前格的放箱后地面无法判断，`riskUnknownCellCount` 记录数量。损坏的覆盖物层用 `overlayUnknown` 区分“未知”与“没有覆盖物”。无效通行／箱子规则只阻止依赖它的预测。
- 当前禁行、清空后潜在禁行、详情、CSV 和 3D 放箱预测保留可判断部分。3D 高低格关联查看独立于放箱预测；未知格不能演示确定的放箱后变化。清空预测也单独记录 `unknownCellCount`。
- 旧预览或尚无局部预测的旧报告尝试重新分析一次；失败保留可读旧结果。底图、对象贴图或 Toy 图集加载失败时，保留成功图层，必要时改用格子简绘；3D 也可用简绘材质。素材失败不改写概率和占用数据。
- 核心地图／坐标确实无法读取时，仍报告错误；上述降级不保证任意损坏文件都可计算，也不把未建模的 Mod 行为宣称为精确结果。

`verify-error-isolation.py`／`.cjs` 比较七类输入的原生与 Toy 精确分数、格子、来源和禁行标记；`--game-root` 检查目录资源。`verify-error-isolation-ui.cjs` 在两版操作禁行显示／CSV、3D、放置／撤销、区域和 Buff，并支持旧预览、图片及图集故障注入。原版完整数据的数值结果保持不变。

## 普通斜坡上的矿石

涉及原版加州高速公路、大矿区抢地盘、心脏地带（作战／巨富）、紧要关头，
共 5 份文件。

原生 Overlay::Mark（YR `5FC570`，RA2 `5DA970`）允许坡型 0～4。
矿石邻接重算（YR `4818E0`，RA2 `476BA0`）调整密度帧，不因为这些普通坡面
删除矿石。YR `Scenario_Load 686B20` 在加载阶段增加 `IKnowWhatImDoing`；
OverlayPack 先创建覆盖物，OverlayDataPack 随后写入密度数据（`5FD2E0`）。
因此这些格子应保留矿石覆盖物，已有 Overlay 会令放箱重试。

`SlopeIndex > 4` 的预放矿石仍不属于精确加载模型，进入近似分析时会显示假设告警：Mark 会拒绝覆盖物，而工具尚未建模
整个后续加载阶段。不能简单把全部斜坡矿石放行。

同时修复 `TIB2_* → Image=TIBxx` 的渲染解析：气候后缀、调色盘等 art 属性
必须读取被引用图像的节。此前直接查 `TIB2_*`，会错找不存在的 `tibxx.shp`，
遗漏实际存在的 `tibxx.tem` 等素材。主地图、小地图、图片导出和 3D 共用该解析。

## 重返巴黎的边界桥梁

RA2 `mp33u4.map` 与 YR `xmp33u4.map` 的 `(18,71)` 是 BRIDGE1。
桥面格为 `(18,69)`～`(18,72)`，都在地图中；前方第三步 `(18,68)` 仅接收
`0x1000` 投影标志，没有 `0x100` 桥面标志。

原生桥初始化函数遇到这个不存在的格子时，把投影位写入地图外的占位 Cell，
不创建额外桥面，也不改变已存在桥面的占用。模型现在允许仅第三步投影越界；
真正的桥面格越界继续报错。

## 已登记、完全未定义的尤复建筑

- `c1a02md.map`：CALA02，`(107,118)`。
- `c3y03md.map`：CALOND02，`(141,75)`、`(106,136)`。

这些类型确实在 BuildingTypes 中登记，但内置 rules、art 及地图都没有对应
定义。不能按“未登记类型”跳过，也不能只因记录生命值为 0 就认为没有占用。

YR BuildingType 构造函数 `45DD90` 将 FoundationData（偏移 `0xDFC`）置空。
没有规则节时，ReadINI 链 `45FE50 → 712170 → 5F92D0 → 410A60` 返回失败，
不会进入读取基础定义的分支。`45EC20` 将空基础返回为仅含
`(32767,32767)` 结束标记的列表；原生地图登记函数 `5683C0` 因而不插入任何
格子的 Content。该结论不依赖记录生命值。

工具为这些对象记录空基础、无贴图状态，并将其写入
`metadata.emptyFoundationObjects` 和对象绘制审计。原始对象记录仍保留。
该例外仅适用于尤复、已在原版注册表登记、且地图／rules／art 均完全没有定义
的建筑；其他缺失定义保留告警并使用已说明的近似处理。

## 重复的 Sight

`c3y02md.map` 在 `[CAMEX01]` 写有 `Sight=6` 和 `Sight=7`。
视野范围不参与当前静态箱子概率、占用或贴图模型，因此允许分析，同时通过
`metadata.irrelevantDuplicateKeys` 保留节、行号和冲突值，并在界面中说明。
这不表示已经确认游戏选择哪个值。

普通严格 INI 解析仍拒绝冲突值；地图分析只为 Sight 提供这一例外。
Strength、基础、通行、箱子规则等其他冲突键和重复节继续拒绝。

## 验证与范围

- `verify-remaining-maps.py`：上述 10 份地图完整概率与渲染分析；
  无缺失覆盖物或建筑／单位贴图，原始对象保留，危险输入仍拒绝。
- `verify-map-loading-native.py`：两个版本各 3,840 个边界桥格对照、
  各 27 个矿石坡型／邻接用例；YR 空规则节返回链、两种生命值下的空基础，
  以及非空 1×1 基础的正向对照。
- `verify-realmap.py`：冰天雪地全部 39,601 个初始坐标、114 个独立分数概率
  分布及六种气候回归。
- `verify-official-maps.py`：248 份原地图 SHA-256、目录合并和选择校验。

原生测试在 Unicorn 隔离内存中执行固定哈希的原程序指令，未启动游戏、
未修改游戏文件。INI 查询、分配器、通用对象服务和重绘等夹具替代项在脚本
中逐项标明。该验证不是完整对局试玩，也不证明动态路径可达性。
程序指纹见 [桥梁研究](bridge-crates.md)。

## 官方缓存重建与验收（2026-11-09）

当前标准／队伍联盟目录共 131 个菜单项，对应 294 份版本／布局报告，按原文件哈希去重后为 278 组缓存。使用当前引擎重新生成全部数据，逐组检查压缩、解码、精确概率、禁行标记和有序来源；所有数值负载与重建前一致。模型指纹为 `4f9f6f45d809f0bd4f74de209c5ab2a31067f5099124f5091c72fc814b21b851`。

重建必须调用 `build-official-precomputed.py --output 新目录 --jobs 4`，不能仅把旧清单的模型指纹改成新值。随后使用 `verify-official-precomputed.py --data 新目录 --render --all-layouts` 验证：缓存／现场计算的概率、全部格子、搜索顺序、渲染像素及 CSV 一致；失配、损坏和强制重算仍保留原有保护。

Toy 的 `toy_probability_refresh.refresh(..., jobs=4)` 支持并行刷新，默认仍为串行。所有输入先校验哈希，每份报告保持无损往返验证，共享列文件用临时文件原子替换，避免同名源表被并行读到半份内容。原始布局／美术来源指纹保持真实来源；概率来源另行记录。同步把 294 份区域通行缓存更新为版本 4，沿用当前的单位、无敌对象及桥面规则，未重新生成原美术素材。

`verify-official-precomputed.py --toy Toy目录` 逐项比较两版全部 294 份报告及 278 组搜索；`verify-toy.py Toy目录 --directory-only --mode standard --mode teamgame` 校验目录、素材、依赖、导航和来源数据，不要求 ZIP。`build-toy.finalize(..., make_archive=False)` 也只生成完整目录清单，保持既有压缩包不变。

`verify-official-cache-ui.cjs` 使用原生缓存的精确签名，实际从两版地图选择器加载白令海峡及五种气候，检查 Buff 后台计算／视图、编辑工具、放置及撤销；Toy 同时检查无分析 API 请求。重建后的完整版通过原先受旧指纹阻挡的 9 项发布预检。此轮只更新本地运行目录，未打包、提交或推送。
