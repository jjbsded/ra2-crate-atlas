# 大量放置布局的 Buff 期望性能

2026-11-08～09。适用于完整版与 Toy。本文描述全格独立假设的 Buff 期望；真实布局的箱子概率仍使用原有精确整数、有限次数重抽模型，不改计算口径。

## 实测问题

测试原图为 `SAVE537E-20261104-130952-917129.yrm`，120×120，57,121 个随机起点。导入布局含 5,572 项：油井废墟 2,272、矿石 2,567、兵营 707、船厂 26。全格计算有 11,913 个非直接求和场景，需要重查 89,463 个起点依赖。

旧实现的浏览器首次 Buff 等待约 130 秒；单独重测旧数值算法约 149 秒。独立剖析约 171 秒，其中 169.5 秒用于为独立假设反复建立 CRT 重抽直方图，超过总开销 99%。绘制最终图层约 29 ms，批次发布最大约 7～8 ms。不同环境的耗时不能直接相加；独立剖析还包含仪器化开销。

优化后，同一导入布局的冷 Buff 计算：

| 阶段 | 完整版 | Toy |
| --- | ---: | ---: |
| Worker 搜索模型准备 | 231～242 ms | 226～232 ms |
| 场景扫描、权重计算与发布等待 | 981～1,074 ms | 1,047～1,092 ms |
| 最终图层绘制 CPU | 24～27 ms | 25～26 ms |
| 从切到 Buff 到图层可用 | 1.37～1.49 s | 1.44～1.55 s |

这是本机样本，不是所有地图的耗时上限。源数据打包可以与其他后台发布重叠，界面状态中的各项墙钟时间不应简单相加。实际全场 17,982 个正值格与旧算法逐格对照，最大绝对误差约 `1.25e-14`，低于既有 `1e-10` 数值验证容差；实际箱子概率的整数结果不变。

辅助 Worker 构造不可用时，同一方案回退协调 Worker 约 3.55 秒，数值、任务取消和真实放车／撤销仍通过。白令海峡数字显示临界缩放的平移回归中，Buff 图层帧内工作 p95 约 0.8～1.0 ms，整帧 p95 约 4.4～4.7 ms，底图重建为 0。

## 权重计算

`buff-expectation.js` 将一个目标格的计算分成 `scenario` 与 `complete`：前者只重查依赖该候选的起点，生成终止函数差量、窗口贡献和需要的候选长度；后者在权重返回后完成求和。原有同步 `value` 继续消费同一实现。未参与候选搜索的格子仍直接读二维前缀和；终止函数没有改变时仍复用基准权重。

`buff-weight-kernel.js` 保留同一逻辑帧内的相关性。对候选长度 1～24，先条件化 2、3 的幂对应的 144 个余数，再将 5、7、11、13、17、19、23 的互素因素作为独立组处理。固定条件下，终止起点数写为 `T = T0(1+z)`，使用中心化矩展开 `1/T`。独立组的矩通过二项式合并；条件权重仍按对应的候选余数投影，不能把平均终止率代入倒数。

展开阶数自适应。仅当倒数展开的相对余项界与忽略的有限重抽尾项各不超过 `2e-17` 时使用快路径；上限耗尽可能有意义、终止数可能为零或展开不能在允许阶数内收敛时，回退原 CRT 直方图和完整有限次数公式。此容差用于双精度显示计算，不替代真实布局的精确整数概率。

同一源模型预备各组的矩和补集投影，局部假设只修改涉及的组。只求当前窗口及差量实际需要的候选长度；共享缓存按终止函数的规范签名合并，并记录已经求出的投影位集。后续窗口需要更多长度时扩展位集，不把缺失投影当成零。

## 并行与取消

`buff-expectation-worker.js` 是协调方，地图搜索、反向索引、二维前缀和只准备一次。先合并相同终止函数的需求，再交由 `buff-kernel-pool.js` 和 `buff-kernel-worker.js` 计算权重；辅助 Worker 不复制整张地图、候选数组或搜索索引，只接收基准终止计数、局部差量、起点数、次数上限和所需投影，返回可转移的数值缓冲区。

大图且可参与候选的重试格达到 2,048 格才启用池；还要求至少 4 个逻辑处理器和浏览器内存分档至少 4 GiB。线程数受逻辑处理器、内存分档约束，最多 4 个，保留主界面余量。较小任务使用协调 Worker，避免线程启动成本。线程创建／加载失败会关闭池并由协调方继续计算。

布局或半径被新请求取代时立即拒绝旧等待者，辅助任务在片段边界检查代际；旧批次不能提交新字段。布局改变会释放旧辅助模型，切到轻任务时关闭辅助 Worker。只切换视图不会取消数值计算，也不会丢弃已经提交且仍有效的图层绘制结果。加载状态分别说明「计算 Buff 期望」和「绘制 Buff 期望图层」。

回到前台后的短暂输入保护由 `interaction-priority.js` 协调，数值分片、结果写回及辅助线程派发／发布可以暂停后继续，不重置源模型、半径缓存或计算口径。实现与恢复压力测试见 [首次拖动说明](bulk-edit-performance.md#回到前台的首次拖动2026-11-10)。

## 模拟编辑后的隐藏预计算

完整版的常驻模拟会话原先只在 `loadResult` 预热全格数值，局部 `applyProbability` 没有对应触发，导致箱子视图中编辑后需等到切换 Buff 视图才计算。现在在精确箱子概率、格子查找表和当前报告安装完成后调用 `buffField.update`；不等待单位美术图像或完整导出报告。Toy 继续在新报告载入时预热，共用相同的 Worker 协议。

- 隐藏时合并 160 ms 内的概率修订；按住画笔连续绘制时，保留最新目标，松开后才启动。显示全格 Buff 或显式等待结果时立即处理最新状态。
- 接收新修订时立即提高代际、丢弃旧发布批次并取消旧计算。辅助线程正在计算时直接终止过期线程；未完成结果不能写回新布局，也不能进入完整数值缓存。不存在逐次编辑依次执行的待算队列。
- `buff-source.js` 分开保存数值槽位和地形几何。常见局部编辑复用坐标索引、多边形缓冲区，仅按槽位传输变化及必要的系数；写时复制保留前一缓存的不可变性。Worker 确认其已接收的源编号；缺少差量基准时使用缓存完整输入回退，不重新打包地图。UI 最多保存两个源缓存，待执行的改动日志只有一份。
- 全图系数发布不在概率安装回调里建立大 Map，改为后台分片扫描。打包、批次写回均按约 2 ms 预算让出主线程。隐藏计算的辅助 Worker 最多两个，协调方额外让出执行时间；隐藏数值到达不绘制 Buff 图层或重建底图。真正改变搜索输入时仍准备新搜索模型，几何复用并不代表跨布局复用旧概率。

本机完整版＋本地游戏目录，以上 5,572 项布局中单次放车、连续绘制八辆灰熊：最新输入发给 Worker 后全格结果约 1.87～1.94 s；局部输入整理约 0.2～0.3 ms；包括初次完整源在内，`postMessage` 最大约 3.8 ms；结果写回最长分片约 2.2 ms。连续绘制帧间隔 p95 约 7.5 ms，八辆画笔过程合并为两个数值启动，过期启动被取消，只发布最新完成结果。这里的约 1.9 s 是后台全图完成时间，不是附近箱子概率或放置图像的显示延迟。

切到已预热视图不增加数值任务。该次放置格的期望与最新精确箱子系数求和对照，误差小于 `1e-10`。Full／Toy 大布局回归同时覆盖半径快速替换、视图往返、相同输入复用、缓存平台期，以及放置／撤销后的全格一致性。

## 缓存与内存

- 权重缓存按实际数组字节、签名和固定开销估算容量，使用 LRU，依据浏览器内存分档限制到最多 64 MiB；没有固定 256 项的过早淘汰。
- `buff-field-cache.js` 仅保存完整数值场，按缓冲区与保守 Set 开销计入最多 24 MiB 的 LRU。部分计算不能进入缓存，换布局时清空；写入后只读，下次计算先复制再修改。
- 同一地图、相同次数上限以及逐字节相等的搜索标志／状态数组可以复用模型及完整数值场，不因报告对象换了身份而重建。比较不使用可能碰撞的散列。几何数据仍跟随当前报告更新。
- 已完成半径恢复按小批次发布，既清除大半径留下的旧值，也保留主界面响应。测试中的恢复 Worker 工作约 2～3 ms，不含后续界面绘制。
- 本案例首次权重缓存约 11.9 MB；往返半径 3、4 后稳定为约 12.5 MB，两个完整数值场约 6.7 MB，重复操作不再增长。浏览器内存分档是容量提示，不是操作系统实时空闲内存；缓存不会预先分配到上限。

## 废墟与最终失败率

废墟和矿石所在格不能落箱，但可进入搜索候选，选中后在同一次随机生成调用中重试，最多 1,000 次。本布局每帧单轮成功率仍有约 56.8%～60.3%，没有终止无箱项；最终失败率约 `1.6×10⁻³⁶⁴%`。这个数字不是废墟面积占比，也不是本轮第一次尝试的失败率。详见 [当前模型](probability-model.md) 和 [废墟机制](random-crate-generation.md#61-建筑废墟为什么触发造箱失败而随机造箱会重抽)。

## 验证

- `verify-buff-weight-kernel.cjs`：独立 CRT 直方图对照全部 300 个余数、局部差量、按需投影、归一化以及有限尾项等回退。
- `verify-buff-expectation.cjs`：独立完整搜索及有限重抽 oracle，含 3 次／1,000 次、空格、水面、缺地形、失败格与各半径。
- `verify-buff-kernel-pool.cjs`：有界派发、源模型复用、过期取消、加载错误与完全释放。
- `verify-buff-field-cache.cjs`：容量限制、LRU、替换、过大结果拒绝和换布局清理。
- `verify-buff-source.cjs`：稀疏更新与完整打包逐项相等、不可变缓冲区、几何及系数复用、基准缺失回退，以及与直接输入相同的独立假设数值。
- `verify-buff-precompute.cjs`：后台预热、连续画笔合并、视图切换、隐藏时完成的图层复用、数值／绘制状态区分，以及分片写回中途被取消的旧结果不能继续发布。
- `verify-buff-live-precompute-ui.cjs`：真实完整版会话的隐藏预计算、连续坦克行、稀疏输入、最新精确概率对照和切换视图不重算。`SIM_RESULT` 选择已分析的大图，`SIM_PLAN` 可加载相应模拟方案；默认小图使用本地 QA 夹具。
- `verify-buff-parallel-ui.cjs`：设置 `SIM_MAP` 和 `SIM_PLAN` 后使用真实浏览器；`SIM_EDITION=toy` 选择 Toy。验证全场数值、快速半径替换、重复视图没有数值或图层任务、缓存达到平台期、相同输入复用及真实放车／撤销的失效；`BUFF_GOLDEN` 可指定旧算法的本地 Float64 对照，`BUFF_DISABLE_POOL=1` 注入辅助线程构造失败并验证回退，加载错误另由线程池测试覆盖。

本地性能记录放在忽略的 `output/buff-parallel-qa/` 和 `output/finite-retry-qa/`，不发布原地图、用户方案、旧算法副本或临时结果。

其他批量编辑阶段（概率发布、图像、区域统计与加载）的后续优化见 [批量编辑性能说明](bulk-edit-performance.md)。
