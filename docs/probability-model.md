# 当前概率模型：有限重抽后的最终生成结果

2026-11-06 按用户最新要求，完整版、Toy、官方预计算与机制演示统一使用 `finite-retry-v2`，最多执行 1000 次尝试。本文替代 2026-11-04 的 `single-attempt-v1` 约定；旧的“忽略重抽／禁止恢复重抽”要求不再适用。

界面只显示 **生成成功** 和 **生成失败**。生成成功必须实际创建箱子；生成失败包含终止但没有箱子的格子，以及连续失败直到次数用尽。技术数据可以保留这两种失败的分解，普通界面不重复解释内部步骤。

## 数学范围

一次生成调用内，逻辑帧 `f` 保持相同；每次重新随机选择起点。模型仍假设各次起点均匀独立，不模拟实机固定种子的 PRNG 序列。布局在本次调用内不改变。

固定帧下，设一次尝试实际生成箱子的概率为 `s_f`，流程终止但没有箱子的概率为 `g_f`，可继续尝试的失败概率为 `q_f`，三者之和为 1。具体格子一次尝试的成功概率为 `p_f(c)`。令 `L=1000`：

```
G_L(q) = (1-q^L)/(1-q)      q<1
G_L(1) = L
P_f(c) = p_f(c) * G_L(q_f)
成功_f = s_f * G_L(q_f)
失败_f = g_f * G_L(q_f) + q_f^L
```

先在固定帧下计算上述权重，再对等权帧余数平均。不得先平均 `q_f` 再套几何级数，这会破坏同一次调用共用帧的条件。坡型等终止无箱格不会继续尝试；Overlay 占用、无候选等可继续尝试，直至上限。成功概率与失败概率以精确整数验证和为 1。

## 不展开重抽循环和大周期

候选数量最多 24。保存每个起点有序候选记录，以及每个成功落点的 `(n,r) → 次数`。重抽不重新执行附近搜索。

固定帧中，终止起点数为 `T_f`。整数几何权重为 `(N^L-(N-T_f)^L)/T_f`。采用 `D0=LCM(1..24)=5,354,228,880` 的公共周期和 `D0*N^L` 的共享分母；300 个 `(n,r)` 的 ID 始终固定。相同贡献签名共享分子，不为每格展开或储存几千位的重复整数。

终止函数的约简周期不超过 144 时，合并该小周期的计数；更大时使用 CRT 因子分解与直方图卷积。先条件化 2、3 的幂，再合并其他互素因子，不枚举五十多亿个逻辑帧，也不对每次重抽重算地图。`T_f=0` 直接归为上限耗尽，避免除零。

## 增量与倍率

局部编辑仍只重新搜索依赖变化格的起点，扣除旧贡献并加入新贡献。终止函数使用精确周期投影生成规范签名：即使候选数量分布改变，只要 `T_f` 对所有帧不变，整个重抽权重核仍复用，只更新局部落点。

只有 `T_f` 改变时才重新合并共享权重，并按原有贡献更新受影响的概率值；不重新搜索无依赖的远处起点。此时远处的最终概率也可能改变，这是恢复重抽后的数学结果。完整版的 live patch 发送局部布局／贡献变化、共享系数与分母，并带 `reweighted` 标记。客户端按贡献签名合并更新其余数值，避免传输所有格子的完整记录；远处数值与新系数必须同时提交，不得混用。

显示的 1× 基准是“仅直接抽中、没有邻格转入”的最终概率，即 `E_f[G_L(q_f)/N]`。JSON 兼容字段 `multiplier` 仍为 `N*P(c)`；界面相对倍率由共享分子与该基准精确比较。原始单次份额保留在 `oneAttemptProbability`。

## 缓存、传输与验证

模型 ID 为 `finite-retry-v2`，`attemptLimit=1000`。旧单次结果不可直接复用；原始地形、美术和有序候选记录可以复用。Toy 使用 codec 3，紧凑配方保存终止计数和无箱计数，解码时重建共享系数。旧 codec 和模型必须重算或拒绝，不得静默当作当前结果。

`finalSuccess` 和 `finalFailure` 为仅有的最终结果字段；`exact.ghostNumerator` 与 `exact.exhaustedNumerator` 是最终失败的两部分，`failureNumerator` 为其和。精确整数保留即使浮点显示为零的微小失败概率。

`verify-finite-retry.py` 使用独立小状态分数求和验证有限重抽，包含“先平均再重抽”反例、无候选、终止无箱、全部失败、1000 次上限及大联合周期；`verify-finite-retry.cjs` 对照 Python/JavaScript 全部共享整数与每格结果。原有增量测试继续对照完整原生搜索、撤销和缓存恢复，并验证权重不变时仍只更新局部。

## 本次验证记录（2026-11-06）

- 独立分数 oracle 40 例，Python / JavaScript 的共享系数与每格整数完全一致；其中包含五十多亿联合帧状态的 CRT 案例。
- 原生完整搜索与增量更新对照 51 次变化，包括空地、混合海陆、空候选、候选上限、状态变化、撤销和磁盘恢复。空地编辑仍只重搜 1 个起点、更新 9 个落点。
- 用户大地图 `SAVE537E-20261104-155756-719000.map`，完整版启用本地游戏目录：复用候选后的整图汇总约 0.70 秒。浏览器实际放置坦克的服务端概率计算约 16–18 毫秒；放矿石改变终止函数时约 0.71 秒，撤销该矿石约 0.28 秒。此为本机样本、仅概率核心，不含首次加载和最终绘图。
- 浏览器实际验证坦克、矿石、撤销矿石、撤销坦克。每次均取当前原生候选，独立重算并逐项对照全部共享系数、每格贡献和浮点值。全局权重改变时，响应仍仅发送 5 个布局／贡献格子及共享系数，客户端按贡献签名更新其余数值。
- 官方 278 份布局仅重算数学汇总，逐份验证原有候选文件和输入规则身份，美术不重新生成。
