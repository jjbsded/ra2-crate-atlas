# 模拟编辑的增量概率存储

适用于完整版和 Toy，2026-11-04。保留原有精确整数概率和原生候选顺序；不是局部概率近似，也不是抽样。

## 数据结构

为每个随机搜索起点保存：有序候选格 ID（至多 24 个）、搜索停止半径，以及用于恢复计算的格子移动／主区域位和 crate／ghost／retry 状态。半径上限沿用原始算法的 31 格。

概率部分保存小整数贡献：每个落点的 `(候选数量 n, 帧余数 r) → 出现次数`、终止无箱贡献，以及各帧的终止计数。300 个候选位置 ID 固定；终止函数不变时复用有限重抽系数，改变时按几何级数和 CRT 直方图更新共享权重。详见 [当前概率模型](probability-model.md)。

完整版实现在 `incremental_probability.py`，用内存 LRU 和 SQLite；候选记录按起点单独存储，事务只替换变化的行。Toy 实现在 `toy-live/incremental.js`，用 Worker 内存和 IndexedDB；每 512 个起点组成一块，只替换变化的块。每种运行时最多保留 4 个布局索引，当前布局和清空对象布局分开存储。缓存是运行时派生数据，不打进 Toy 安装包。

## 更新流程与正确性

1. 比较新旧移动位、主区域位、起点海陆属性和终止状态，得到真正变化的输入格。
2. 至多八个输入变化格时，先查询 16×16 起点块的保守停止范围，再精确检查块内各起点；较大修改使用二维前缀和。这里包含曾被拒绝的格子，不只索引旧候选；因此能发现“原障碍被清除”带来的新路径。
3. 只重新搜索这些起点。先扣除旧候选的整数贡献，再加入新候选的贡献；更新它的停止半径。
4. 比较规范化的帧终止函数签名。相同时只更新变化落点；不同时重新合并共享重抽系数，再复用原贡献更新最终概率。生成失败合并终止无箱与次数耗尽，和成功以精确整数验证守恒。

旧停止方框以外的格子不会影响已完成的旧搜索。反之，方框内变化可能让搜索向外扩张，因此重搜时仍执行完整的原生搜索规则。保留半径 0 的重复候选、环内遍历顺序、主区域筛选以及 24 候选上限。海陆属性变化也属于输入变化，起点自身必在自己的依赖方框内。

无遮挡空地上的一个起点原本在半径 0 停止。放一个单位后，通常仅这个起点需要重搜，将其贡献分给邻近 8 格，因此涉及原格加邻格共 9 个落点。不能将这个例子硬编码成固定 3×3：窄路、大片障碍、海陆交界和远距离搜索可能有更多依赖起点。

当前模型已恢复最多 1000 次有限重抽。候选搜索仍局部更新；仅当终止函数改变时，重抽权重可能影响远处最终概率。以 [当前概率模型](probability-model.md) 为准。下方 2026-11-04 的单次模型计时为历史记录，不代表本次有限重抽的实测。

较大修改的二维前缀和仍会扫描全部起点。小修改复用局部依赖块，驻留接口仅组装需要返回的落点。完整版一次涉及超过 512 个依赖起点时，使用原生 C 批量搜索，并只替换受影响的贡献，避免大量 Python 环搜索反而变慢。

## 持久化、失效与恢复

缓存身份包含地图内容 SHA-256、游戏版本、资源／规则／气候身份、矿物模式、近似模式和搜索模型版本。编辑方案本身不进入身份键：同一地图的最新布局可正向更新，也可反向更新以支持撤销、重做和恢复。

SQLite 使用事务和快照修订号；IndexedDB 使用跨 header／blocks 的同一事务和修订号。若其他进程或标签页已提交不同快照，写入时改存完整快照，不能将自己的局部变化套在别人的基底上。重载时验证维度、记录完整性及校验值；损坏或旧版本缓存重新建立。SQLite 使用 SHA-256，浏览器分块使用字节校验值。浏览器配额不足或禁用持久存储时继续使用内存缓存。

首次建立索引需要完整计算；后续编辑复用。点击“重新计算”仍可显式绕过增量状态，执行完整计算并更新索引。缓存不会改变或覆盖原地图；模拟方案仍保持原有增量导入／导出格式。

## 界面与画质

完整版在概率与禁行判断完成后，先发布 `probability.json`，让热力图和数值恢复显示。地图的无损贴图、阴影和遮挡继续生成，状态栏显示“概率已更新 · 正在更新地图画面 · 可继续放置”。期间保持图片导出、区域操作和 3D 关闭，避免输出未完成的画面；最终报告准备好后统一恢复。

提前发布与最终结果都检查地图身份和编辑修订号。用户继续修改、切换地图或关闭“考虑模拟放置”后，旧快照不得覆盖当前状态。临时显示克隆格子数据，不能污染默认布局或撤销记录。

完整版现在将概率任务与最终绘图分开调度：一个概率计算任务、一个绘图任务，以及至多一个待绘制的最新方案。新方案的概率不再等待旧画面结束；旧画面在安全进度点取消，尚未开始的过期画面直接丢弃。最终绘图仍使用原始分辨率和无损编码；未就绪时保持导出与 3D 禁用。

## 编辑链路的局部更新

完整版保留两个已解压地图的基础布局。地形高度、TMP、规则及原地图对象不因放置而重新解压；同一地图的目录资源上下文也可复用。目录清单、散装依赖内容和来源哈希仍校验；带地图本地 include 时保留文件目录作为资源身份的一部分。

编辑方案与上一方案比较，重建变化对象的实际基础占地。桥梁变更同时覆盖投影写入格及反向高度投影依赖，不能固定限制为 3×3。占用与规则判断沿用完整解析函数；局部路径与完整路径没有两套游戏规则。近似模式也只重新判断变化格，其近似声明保持不变。

未变的格子、规则节及精确概率结果作为只读数据共享。概率计算仅为变化的布局或概率值建立新格子对象，绘图另外取得自己的可变副本，防止绘图字段污染默认布局、撤销结果或下一次计算。`metadata.layoutUpdate` 记录 `decodedReused`、`rebuiltCells`、`reusedResultCells`。

`probability_delta.py` 发布绑定基底修订号的增量快照。除了变化格，只传改变的统计字段；未变的精确大整数系数不重复序列化。客户端同时检查地图、版本、修订号，保留未变格的显示数据及共享大整数。缓存基底失效或校验不匹配时取得完整快照，不猜测应用差量。快照内存最多保留四份。

一笔画完后的合并等待改为 120 ms；按住画笔时仍不提交。概率未就绪时使用 80 ms 状态轮询，概率就绪后的最终画面轮询降为 200 ms。Toy 共用合并等待和显示数据复用；资源/布局缓存及双队列改造属于完整版服务端，Toy 保留其浏览器 Worker 与 IndexedDB 路径。

完整报告包含区域通行数据，避免客户端为同一结果再触发服务端读取和解析完整报告。模拟帧使用快速无损编码，跳过可选的后台二次压缩，避免给即将被下一笔替换的画面反复编码；像素与尺寸保持不变。首次地图加载、显式完整重算、大范围编辑仍可能需要较多工作。

## 完整版实时编辑

驻留会话绑定原始地图、有效资源、布局和搜索状态。目录资源模式显示地图后即开始预热，其他模式在开启模拟放置时准备。编辑期间浏览器合并相邻事件，提交对象、覆盖物和放置记录的差量。概率端复用已缓存的搜索候选与整数贡献，直接返回变化格和汇总值。应用前校验地图与基底修订号。连续拖动画笔时分批提交；直线在松手时提交，撤销仍以整笔为单位。

画面端复用原生 TMP、SHP、VXL 和绘制顺序，按精灵及阴影覆盖范围更新 256×256 像素的图块。满足同高度、无地形物、对象像素不半透明等条件时，可从原生地面图复用底图并合成对象与阴影。其余图块重放原生遮挡和阴影规则，包括桥面及桥头。浏览器独立缓存图像和概率 Overlay。普通编辑只重画受影响的图块；按全图最大倍率归一化的配色在最大值变化时重画可见热力图。

驻留编辑的完整报告仅在明确下载完整 JSON／CSV 数据或重新计算时生成；停笔及切换查看模式沿用已完成的局部图像和概率。PNG／JPEG 图片导出直接使用冻结的当前图像、格子和图层，不要求先生成报告。热力图只等待内存概率差量。画面补丁每批最多传八块，优先更新视口附近；新修订接续时以最后一个完整画面为基底，补齐此前只显示了一部分的区域。会话过期或旧报告无法核对时，使用完整分析路径恢复。目录资源仍沿用目录分析的近似规则假设，精确性指相同规则输入下的整数概率和候选顺序。

查看模式选格时，概率来源通过 `/api/maps/simulation-live/sources` 按需取得驻留会话当前修订的原生候选记录，复用既有来源索引和精确贡献校验，不为查看格子触发报告绘图。索引只缓存当前概率数据，响应提交前核对地图／数据／会话修订。概率差量一经应用就提交合并的区域刷新，不再等待 100 ms 后的完整详情 UI 更新。

2026-11-06 在 `SAVE537E-20261104-155756-719000.map`、完整版＋Steam 本地游戏目录复现：空地放一辆灰熊后切到查看模式，局部画面约 44 ms、概率约 36 ms 已就绪，但旧模式切换又触发全图绘制、遮挡裁切、保存与重新载入，转圈共持续约 16.65 s。移除这项自动任务后，同路径三次全部派生工作完成约 138、117、147 ms；预先拆过建筑的布局再放坦克，三次约 95、107、110 ms。后者仍只重搜一个起点、影响九个概率落点。小样本为本机测量，完整数据下载／强制重算与故障恢复仍有独立耗时。

`verify-simulation-tail-ui.cjs` 同时检查不产生自动完整报告、查看模式来源索引可用，以及明确下载的完整 JSON 与实时结果逐格精确项一致。原始事件、请求与服务端计时位于 `output/placement-tail-qa/`。

验收使用 28,680 格的 `SAVE537E-20261104-130952-917129.yrm` 与其 Steam 游戏目录。原图没有桥梁记录，拆高桥和低桥使用同图副本加入测试桥段。浏览器计时从编辑事件至对应修订的图层绘制，原生对照对全图逐格比较精确项，并对地面和对象图层逐像素比较。记录位于 `output/live-edit-qa/`。

## 区域增删的合并刷新

区域编辑不改变放箱概率本身。增删格子立即按操作顺序写入区域集合；同一笔画仍是一项撤销记录。区域统计、边界路径、缩略图及排名的派生刷新通过 `region-refresh-queue.js` 合并：最多一项正在计算、一项最新待处理状态。新输入替换尚未开始的中间状态，不丢弃实际编辑，也不会在持续拖动时反复推迟首次刷新。

每次计算先冻结区域集合，以约 2 ms 为调度预算分段处理，优先使用浏览器 Scheduler API，在任务间让出主线程；无此 API 时使用计时器。只重建变化的 480×240 世界像素图块路径，其他路径继续复用。完整快照准备好后统一发布统计和图层；期间保留上一份完整画面，工具保持可用，右下角显示“正在更新区域统计…”。短任务仍在主线程执行，并非后台 Worker；单段遇到浏览器内存回收等情况可能超过目标预算。

撤销、导入、切图或取消笔画会使旧任务失效，禁止旧地图结果回写。显式图像导出会先完成最新区域快照，避免导出中间状态。自动保存避开尚未结束的笔画。完整版与 Toy 共用此实现。

## 剩余流程的第二轮优化（2026-11-06）

继续对同一张 28,680 格地图、同一本地游戏目录、1900×1300 视口和两组各三条坦克曲线测量。`output/residual-qa/before-cpu.txt` 的 60 次增删显示：概率汇总虽已只更新受影响落点，却仍每次遍历约 1,200 个在用分布，重新加总成功概率、查找最大倍率并复制完整落点结果；美术阶段也会重新准备全部手动坦克。本轮保留原完整算法作为回退与对照，只优化派生索引和协议，不改变有限重抽公式或官方／Toy 预计算数据。

### 精确汇总和依赖索引

- 每个 16×16 起点块记录块内最大的旧停止半径。查询先筛选可能相交的块，再逐起点检查自己的真实半径，输出保持原起点顺序。半径变化后更新对应块；SQLite 重载时重建这些派生数组，无需修改持久化格式。较大输入变化继续走原前缀和与原生 C 搜索。
- 普通小修改先确认终止函数与 ghost 贡献不变。各候选数量的终止计数若在所有余数上产生相同差量，只需证明这些常数的总和为零；其他情况仍用原规范化周期签名判断。
- 固定系数下，只替换脏落点的分布计数，并检查新旧精确分子差量之和为零。成功／失败总量因此沿用上一份已经验证的精确摘要；最大值用带惰性删除的堆维护，不扫描全体在用分布。堆超过 `2×在用分布数+64` 时压缩。ghost 改变、终止函数改变、大修改、分布缓存过大或分子差量不为零，均回退到完整汇总。
- `Store.calculate(result_keys=...)` 仅筛选接口需要返回的格子，统计摘要、内部全体落点与最大值仍覆盖整图；不传该参数时仍返回全部格子。驻留接口不再为了发送九个落点而先复制约三万个结果。

### 图像、显示和传输

- `ObjectPainter.prepare(..., event_groups=...)` 可同时提供原生对象事件分组，默认输出保持原样。仅在已经通过验证的 MTNK 空地路径中，Scene 按对象 ID、记录、地面高度和配色复用事件，只准备新增／改变对象并重排其旧／新图块。建筑、桥梁、覆盖物及其他布局继续完整准备；进入和退出快捷路径会清理索引，保持原深度、炮塔、部件和阴影顺序。
- 概率变化直接提交带原安全边距的世界矩形，由视口按物理像素图块合并一次。取消此前“先扩大为 256 世界像素图块，再扩大为 256 物理像素图块”的重复取整。热力图、占用和禁行标记都保留原样。
- 每批概率文字只设置一次相同字体／描边状态，按不可变显示数值对象缓存一位小数标签；选中格仍重新设置完整文字样式。字体、位置、大小、描边与抗锯齿均不改变，没有增加文字缩略图或降低分辨率。
- 新客户端提交 `planEcho:false`，概率与图片响应不再重复回传完整编辑方案。客户端按修订号保留至多 16 份已提交方案，图片可先于概率完成；找不到对应方案时自动补取完整方案。旧客户端不传该字段时继续收到完整方案。补取走同修订图块缓存，不重新绘制。
- 新客户端提交 `compact:true`，省略未变化的概率摘要和失败分子字段；改变的字段仍按原路径提交。权重变化仍发送完整新系数并全局重加权。未启用此选项的接口保持原完整响应，导出方案与完整报告格式不变。

## 持续慢路径与驻留会话恢复（2026-11-06）

复现到两处会使刷新前持续变慢的问题：驻留会话仅保留两个，普通浏览页的自动预热可能淘汰正在使用的编辑会话；前端收到失效错误后退回完整报告，后面的普通编辑也会继续生成完整报告。另一个问题是已有模拟方案的近似报告在重建会话时，把原始格子错误标记成已应用该方案，令增量重建没有脏格，最终因精确概率校验不符而无法启用驻留编辑。

- 内存上限仍为两个会话，优先淘汰没有编辑、没有在途布局的预热会话；所有槽位都已编辑时保留 LRU 行为。普通浏览页不再优先挤掉活跃编辑。
- 失效返回 `LIVE_SESSION_EXPIRED`。概率和图像请求共用一个重连任务，每个目标修订至多自动重连一次。以已确认的概率方案、已完整显示的图像方案分别恢复；有未完成图像时重放其变化并恢复前一完整图像，留下正确的清理区域，确保撤销后不残留未确认的对象。
- 重连期间保留现有画面和编辑；迟到的旧会话响应不再提交。重连成功后仅重试当前增量，正常恢复不生成完整地图报告。必要的异常回退完成后，也会重新准备驻留编辑。
- 初始化原始近似基线时明确使用 `simulationPlan=None`，之后才应用报告中的真实方案。已有纯灰熊报告也保留清地快速路径；其原生事件基底排除已加入的模拟坦克，避免重复制图或重复阴影。
- 等待概率时，脏格比较双方都使用派生区域色方案，避免把「原始计划无 regionColor」与「已显示方案有 regionColor」误判成所有模拟对象都变化。

独立测试服务、本地游戏目录、`SAVE537E-20261104-155756-719000.map` 的实际复现：旧版会话淘汰后两次普通放置分别约 16.7 秒、15.4 秒，产生两份完整报告。修复后，打开额外的普通浏览预热再放置约 56 ms；强制让所有会话槽位都被编辑占用并淘汰旧句柄时，自动重建约 4.7 秒，之后下一次放置约 45 ms，全程没有完整报告请求。冷启动和真正失效后的会话重建仍有一次开销；没有将这段等待伪装为已完成。该记录是本机样本，不是固定延迟承诺。

`verify-session-retention.py` 检查原内存上限、预热替换、编辑会话 LRU 和失效编码；`verify-live-resume.py` 对照完整概率和原生像素，覆盖两阶段修订一致／错位、部分图像撤销、已有灰熊报告的快速路径；`verify-live-recovery-ui.cjs` 在独立端口淘汰真实会话，检查普通浏览预热不干扰编辑、重连后保持驻留模式、没有完整报告及后续编辑恢复快速响应。证据位于 `output/live-recovery-qa/`。

## 会话失效来源与基线复用（2026-11-07）

驻留会话没有 TTL，也不会因等待数秒自动过期。句柄失效有三个入口：容量为两个的会话池淘汰旧句柄；客户端换图、重算、关页后主动释放；服务重启清空内存。此前换图和关闭页面没有主动释放，已经无人使用的已编辑会话仍可能占用槽位。现在优先替换未编辑的预热和没有在途请求的会话；全部槽位都在使用时仍保留有界淘汰，不无限增加完整地图副本。

失效响应保留 `LIVE_SESSION_EXPIRED`，另提供 `reason`：`capacity-evicted`、`released-by-client` 或 `unknown-or-server-restarted`。最近 32 个失效原因用于诊断，超过范围的句柄归入最后一项。前端 `state.liveRecovery` 保存原因和重建各阶段计时。该信息属于诊断数据，不增加普通界面文字。

### 原重建成本

此前约 6.3 秒是单次浏览器端到端样本，不能事后精确拆成各函数耗时。本轮在同一本地游戏目录和 `SAVE537E-20261104-155756-719000.map` 上，直接测量原重建路径：热资源两次约 4.78／5.49 秒，首次进程冷启动约 9～10 秒。一次 4.78 秒样本的分布为：

| 阶段 | 耗时 |
|---|---:|
| 读取报告、原图与资源有效性检查 | 143 ms |
| 重新解析并重建原始布局 | 1,270 ms |
| 近似布局适配 | 363 ms |
| 构造精确起点记录、反向贡献和依赖索引 | 185 ms |
| 精确概率汇总 | 201 ms |
| 原生素材准备、对象事件、地形与覆盖物索引、底图解码 | 2,473 ms |
| 默认坦克素材预热 | 34 ms |
| 格子编码、结果核对及其他初始化 | 104 ms |
| 恢复已确认的编辑方案 | 5.5 ms |

CPU 剖析确认主要重复成本在 SHP／VXL 素材准备、资源文件定位、布局深拷贝和逐格场景索引；恢复两辆坦克的增量本身很小。证据见 `output/live-open-qa/before.json`、`before-detail.json`、`before-cpu.txt`。

### 复用与生命周期

- 服务保留一份未被编辑的、已经通过精确概率核对的地图基线，最多两个活跃编辑会话。新会话不再重复解析地图、解码素材、遍历地形建索引或执行全图搜索／概率汇总。
- 每个编辑会话复制独立的布局游标、格子编码、搜索记录列表、半径数组、反向贡献计数、概率缓存容器、脏图块和锁。只读的格子基线、整数系数、素材像素和原始事件可以共享；新旧编辑及撤销不能相互污染。
- 地面图片按引用计数释放；替换基线时仍在使用旧地图的会话继续持有有效像素。原生体素的索引帧和阴影缓存也共享，工作进程的请求管道由锁串行化，配色仍逐次使用各自参数；最后一个引用才关闭工作进程。
- 每次打开仍读取并核验原地图和资源来源，不跳过目录／规则／art 校验。基线键包含报告及搜索／底图文件的路径、尺寸和修改时间、原地图内容摘要、rules 内容摘要、art 摘要和资源指纹。输入变化导致重新构建或要求重新分析。
- 换图、重载和关页发送释放请求；保留到浏览器前进／后退缓存的页面不提前释放。每次在途打开有独立 lease，取消加载或离开页面时即使还不知道服务端句柄，也能撤销该打开，避免迟到的预热占用槽位。最近 128 个取消 lease 有界保留。
- 已进入服务端的概率／图像请求拥有使用计数；淘汰或释放只撤销后续访问，等在途请求退出后再关闭底图和工作进程，避免绘制过程中释放资源。

### 优化后测量与验证

独立端口真实浏览器强制淘汰同图编辑会话后，服务端恢复约 **174 ms**：输入校验约 **124 ms**，独立状态复制约 **37 ms**，编辑恢复约 **11 ms**，其他调度约 **2 ms**。从点击到附近概率、美术和等待标志全部完成约 **254 ms**；随后两次普通放置约 **53～60 ms**，没有完整报告请求或警告。端到端包含失败请求识别、重连往返和局部绘制，不能只用服务端 174 ms 代替。数值为本机样本，参见 `output/live-baseline-recovery-final.log`。

真正的首次冷加载、服务重启、基线换成其他地图或输入变化仍要重新准备；不承诺所有重建都在 254 ms 内。共享基线及生命周期优化属于完整版后端，Toy 不使用这套原生会话池。

`verify-live-baseline.py` 检查热恢复不进入解析／场景构建、真实编辑与基线隔离、报告和资源变化失效、共享工作进程的并发与关闭。`verify-live-resume.py` 检查各阶段错位、部分图像撤销及已有编辑报告的精确概率和原生像素；`verify-session-retention.py` 检查淘汰原因、在途关闭安全及取消 lease；`verify-live-lifecycle-ui.cjs` 验证刷新、关页以及响应未到达时关闭的真实浏览器释放行为。

## 启动、首次载图与目录切换（2026-11-07）

本轮分别测量冷进程服务启动、空白页面资源检查、首次上传地图出图、模拟编辑可用和本地目录切换。基线与最终版本均使用本地游戏目录、同一张 28,680 格的 `SAVE537E-20261104-155756-719000.map`、1900×1300 Edge 视口。测试会产生新结果文件，不修改原地图或游戏文件；目录保存测试使用隔离的临时配置。

### 已修改的流程

- 目录文件名查找在一个 API 请求／分析批次／绘图批次内共用目录索引和已解析的根路径，嵌套批次复用同一索引，不跨请求保留。大小写歧义、路径穿越和符号链接边界检查继续生效。批次结束后清理线程局部状态，后续请求能看到新文件与新规则。
- 完成目录分析后，将已经读过的规则与原始素材上下文放进现有的两个条目的上下文缓存。发布前重新核验资源指纹，并逐项比较已读取的散装文件摘要，大小和时间戳未变而内容改变时也拒绝复用。带地图本地 include 的情况仍由原加载器处理。每个请求得到独立的 reader 缓存与规则节字典，避免修改一份有效规则污染其他会话。
- 已完成的最新报告按实际落盘路径、尺寸和修改时间交给后续消费者，不再立即重新解压和解析同一份 JSON。仅保留一份直接交接；普通报告读取仍为两个条目的 LRU。文件替换会失效。相同报告、资源发现和资源状态的并发请求合并在途工作，失败可重试，不给不同输入共用结果。
- 初次原生编辑打开使用 `includeSource:true`，在已经校验的同一上下文中返回编辑源数据与会话。首次不再另外请求 `/api/maps/simulation-source`，也不并发做两份目录校验。现有源数据接口仍用于兼容与失败回退；普通重连不附带大型源数据。
- 报告元数据就绪后即可启动编辑预热，与图片解码和页面准备重叠；正式提交同一个结果时复用这一份预热，不取消后重开。切换目标、读图失败和关页仍取消过期预热；切换默认／模拟布局不会额外打开会话。
- 新图片已经用 method 0 无损编码，取消分析结束后立即启动的 method 3 自动二次压缩，避免与首次图片解码和编辑初始化争用 CPU。像素与尺寸不变；新文件可能比二次压缩后的文件更大。`map_images.optimize` 的独立维护能力保留，普通载图不再调用。
- 保存目录复用本次发现结果，不立刻重新枚举一次相同目录。保存当前同一指纹仍沿用已有地图，不重新分析；实际切换资源后仍重新分析以保证正确性。
