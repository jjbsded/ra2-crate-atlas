# 大规模放置与删除的计算、绘制和加载优化

2026-11-09。接续 [Buff 期望性能优化](buff-expectation-performance.md)，本轮检查真实布局的概率发布、区域统计、图像合成、撤销及页面加载。计算口径、原始地图和增量方案格式不变。

## 具体修改

### 精确整数与显示数据

- `finite-retry.js` 用高 112 位构造商的上下界，必要时以完整整数比较确定商；不能唯一判定时回退完整除法。整数商、IEEE 754 舍入、次正规数和溢出语义保持一致，没有把精确概率替换成浮点近似。
- 分母信息采用最多 32 项的 LRU；位数由十六进制求取，避免反复生成长二进制字符串。
- `probability-display.js` 在重加权和显示建表之间共享系数、分母及按落点分布合并的分子，避免再次计算相同整数。
- 用于导出的基准约分数改为惰性求值。普通绘制不执行大整数最大公约数运算；导出、读取元数据时仍取得同一精确约分结果。

### 区域统计与临时图像

- 修复概率刷新沿用旧 `rebuiltTiles` 计数而误使区域颜色缓存失效的问题。
- 相同原图重新载入模拟结果时，逐格核对投影、地形高度、可见面和可选范围。几何确实未改变才复用区域路径、颜色缓存和表格控件；概率统计仍按新结果更新。桥梁或其他可见几何变化会使核对失败并正常重建。
- 尚未合入正式图块的放置对象使用一个视口大小的临时画布；同一位置和版本只画一次。鼠标提示、加载标志更新不再反复排序并绘制数千个待提交对象。布局、视野、素材、区域色或透明度改变时失效。

### 完整版图块

- 原先 64 块的地面缓存容易在 300 多块更新中反复淘汰，现改为按字节限制的按需 LRU：平坦地面 128 MiB、地面编码 32 MiB、当前图块编码 32 MiB、历史图块编码 64 MiB。没有预先分配这些空间，也不无限增长。
- 历史图块按桥梁状态、覆盖物及变体、物体顺序与位置、图像和阴影身份建立签名。撤销恢复相同内容时复用编码；不能证明相同则重新绘制。
- 图像与阴影使用稳定的图像身份，避免对象释放后 Python `id` 被复用造成误命中。
- 无损 WebP／PNG 编码使用最多 4 个线程，与下一图块的绘制重叠；输出顺序及精确 RGBA 像素不变。会话关闭时回收线程与缓存。
- 浏览器地面缓存按解码像素和 URI 大小计费，上限 96 MiB／512 块；服务允许对应数量的地面确认。丢失缓存时仍可重新发送完整地面。

一个回归样本中，撤销建筑消除的服务端图像绘制总耗时约 179 ms，其中光栅化约 25 ms、编码线程累计约 61 ms；旧实现这两项分别约 7.4 s 和 2.8 s。线程耗时可以重叠，不应把它们直接当作总等待相加。

### Toy 图像与加载

- 预览 Worker 支持按源版本、方案版本复用源数据和解析结果，并且裁图只返回独立数组，不能裁坏后续图块的基图。旧调用方式保持兼容。
- 新增单个可替换的图像 Worker，使用与界面相同的 `mixed-painter.js` 像素合成器，保留地形接收面、建筑遮挡、桥面和阴影规则。图集位图每个布局传一次；每次返回图块位图。
- 新报告的总览图也在后台以原来的 2048／1280 级别生成，预热后交给原图像源，避免首次绘图时在 UI 线程重画全图；不降低原来的分辨率。
- 图集像素缓存为按需 64 MiB。布局替换、取消、页面重置及整批图块完成时释放对应 Worker。过期结果不能覆盖新结果；不支持 Worker／OffscreenCanvas 时回退原合成器。

### 服务入口加载

本地 HTTP 监听队列从 Python 默认的 5 提高到 128。浏览器、分析 Worker 同时加载脚本时，不应因连接尚未被接收而随机丢失关键脚本。该队列是待接收连接数量，不是预先创建 128 个计算线程。

### 精确权重历史

完整版新增 `probability_kernel_cache.py`，在进程内按需保留最多 64 MiB 的精确整数权重。键包含随机起点总数、次数上限及完整终止余数计数；不只使用相加后的函数签名，以免改变 `weightPeriod` 等诊断字段。不同资源和布局只要输入完全相同，就可以共享纯数学结果，资源文件本身仍按原规则校验。

缓存仅保留最终系数、分母和必要诊断，不保留 CRT 计算中体积较大的条件直方图。可写字典和列表交给各调用方独立持有，避免报告之间的修改污染。并发请求相同键时合并一次计算；失败后可重试。该缓存不会把“与上一布局系数相同”误报为真：布局改变后，即使命中历史权重，仍正确重新整理受影响概率并重加权显示。

本轮真实布局中，撤销单位、撤销建筑和全部恢复的概率汇总分别约 66、85、90 ms；上一轮对应约 2.5 s、2.8 s、0.75 s。一个独立布局样本的纯权重构建为 559 ms，历史读取约 0.06 ms，持有约 2.1 MiB。纯权重时间不等于完整概率求解时间，后者还包括布局更新、候选依赖和汇总。

### 协作式概率整理

`probability-display.js` 的同步和异步重加权共用同一个精确计算生成器。异步路径约每 3 ms 让出主线程，输入记录始终不变；只在全部完成且地图／会话仍匹配时统一提交。取消后不会发布中间结果。原来同步使用的导出和测试入口保留。

原生编辑发布和中间概率快照均等待整理真正完成，之后才推进已应用版本。窗口切图、切回默认布局、重连或更新版本时的有效性也会在等待后再检查。整段整理的墙钟时间仍可能超过 100 ms，但不再等同于连续占用主线程那么久。本轮大布局主线程峰值约 56～125 ms，另有首次导入／初始化成本，不代表已经完全没有长任务。

### Toy 数字分析源复用

`toy-live/analysis-source.js` 在分析 Worker 中只保留一份当前源数据。后续编辑发送源版本和方案；收到结果时不再重复返回客户端已有的地图源数据，也不重复传输原文件字节。新地图、版本更换、Worker 取消和重启会正确重新发送。无版本标识的旧请求仍兼容。

客户端在首次分析之后才准备树种和矿石限制等素材上下文，所以 `simulationAssets`／`allowOre` 作为小上下文继续同步，不能只缓存最早的原始解析结果。已补充 TREE16 等实际树种放置与撤销的两版浏览器验证。数据复用不会使矿石／树木放置恢复旧的默认规则。

开发用 Python 静态 Toy 服务也把连接队列提高到 128，并验证突发脚本加载。便携 Toy 的 PowerShell 启动器仍使用其原有 HTTP 监听机制。

- `verify-probability-kernel-cache.py`：精确权重与诊断一致、1000 次上限、可写结果隔离、按字节淘汰、并发合并及失败重试。

- `verify-toy-analysis-source.cjs`：完整源、源版本、素材上下文、取消重建及旧请求的兼容。

## 长任务续查：后台像素、分块传输与绘图流水

继续使用同一大地图、5,572 项方案和追加 500 辆灰熊，采样 CPU 调用栈并分别记录后台工作与主线程长任务。没有改变概率算法口径、图像分辨率、过滤方式或增量方案格式。

### 完整版精确内核

`probability_kernel_worker.py` 按需启动一个驻留的 Node 辅助进程，复用 `finite-retry.js` 的精确整数算法。只传入终止余数计数、起点数量和次数上限，不传地图文件、图像或游戏资源。周期较小的简单问题继续在 Python 内计算，历史命中也不启动辅助进程。

独立样本中，Python 冷权重约 536 ms；V8 首次约 264 ms，预热后约 186～191 ms。跨进程后也减少对 Python 图像线程的 GIL 争用。全部 300 个整数权重、共同分母、耗尽次数及诊断字段与独立 Python 实现完全一致，不以浮点近似替代。

辅助进程限制为 512 MiB V8 堆，串行处理数值请求；输入／输出管道有独立线程和超时。缺少 Node、进程退出、格式损坏或管道无响应时关闭辅助进程并回退 Python，退出时回收进程和管道线程。可用 `CRATE_ATLAS_KERNEL_BACKEND=python` 强制原路径以便对照。64 MiB 精确权重历史继续位于上层，不重复保留中间 CRT 直方图。

### 完整版图像流水

图像发布只预取一批：上一批解码和显示时，服务端可绘制下一批。过期响应有独立错误接收，不会产生未处理拒绝或覆盖新会话。首次仍请求 8 块，后续按实测绘制时间在 8～16 块间调整；冷图块较慢时维持小批，历史图块很快时减少请求次数。每批仍给界面显示机会，没有改成等待全部完成才发布。

### Toy 的残留同步像素路径

采样发现，区域统计的小裁图会触发整块 512×512 原始像素重建；另一个任意矩形局部预览仍同步合成，追加 500 辆坦克时可产生约 0.6 秒长任务。现在两者都使用同一像素合成器的后台实现。

裁图先按原规则绘制原始分辨率图块，再按原采样方式缩小；没有直接在低分辨率合成来换速度。裁图源像素缓存按当前场景持有，目标为 16 MiB／128 项；复用同一取景与大小，不因区域颜色或透明度改变重画背景。独立裁图 Worker 空闲 1 秒后释放；旧场景、旧样式和旧文档的结果不能发布。原同步绘制作为不支持后台 Canvas 时的兼容回退。

### 数据传输与报告提交

`toy-live/report-transfer.js` 将大型源数据和完成报告的格子按 256 项分块传递，保留坐标顺序、数值、字段和原来的来源二进制。源数据发送约每 3 ms 让出主线程；报告接收由多个较短消息任务完成。取消时不发送结束标志，接收方核对完整性，不能把半份报告交给地图。旧的一次性消息协议仍兼容。

`probability-display.js` 的显示建表也改为同步／异步共用的生成器。报告载入期间按约 3 ms 分段预热，正式提交复用同一结果；导出和已有同步调用继续可用。数值、分母、阈值和最大倍率一致。完成时间可能略受调度影响，收益主要是避免整张表在一次提交任务内连续计算。

### 新增验证

- `verify-probability-kernel-worker.py`：全权重与诊断一致、1,000 次上限、并发请求、损坏／退出／不读管道的辅助进程及干净回收。
- `verify-toy-raster-ui.cjs`：32 项逐像素对照，含任意矩形局部预览、非整数取景、非等比缩略图、阴影、桥面遮挡和取消。
- `verify-region-thumbnails.cjs`：异步完成保留 Canvas，旧样式和换图不发布。
- `verify-toy-report-transfer.cjs`：空／大报告和源数据完整一致、分段让出、次序与完整性检查、过期取消和旧协议。

### 编辑模型

原先每次 `paint` 都深拷贝整份方案，再序列化前后两份作比较；点到空地也付出同样成本。现在仅复制可编辑容器，未改变的对象记录在内部历史间共享，按字段识别无操作。公开的 `plan`／检查点仍返回独立快照，不能由调用者改坏模型或历史。

原始对象的占地索引随模型建立一次；模拟对象的空间索引按增删记录更新。小范围删除仅查询相交对象，保持原来的对象和占用顺序；大范围一键操作保留顺序扫描。恢复改为沿原始占地索引扩张重叠基础，不再反复扫描全部对象；没有命中桥梁时不构建桥梁用的当前地图。恢复笔画也不提前准备无用的“单位覆盖下层”保护；若同一事务随后使用删除，仍按笔画开始时的布局补算保护。

修改格数按内部方案缓存；连续放置向同一容器追加时，使用长度更新缓存，并清理已预热的活动对象索引。索引只属于当前模型，活动状态及计数缓存使用弱引用；不会为每一步历史保留一份完整空间索引。

### Toy 大图导出

同一布局导出 13,905 × 7,151 图片，旧路径的素材合成连续阻塞主线程约 3.08～3.44 s；JPEG 编码本来已异步，不是这一段的来源。新路径为大规模混合素材单独创建导出 Worker，按最终输出像素分成最多 512×512 的块，逐块绘制到导出画布。只保留一块在途像素，不另分配第二张完整地图，也跳过场景外的空白块。导出结束／异常时释放 Worker、素材副本和临时画布；换布局和裁图任务不取消正在导出的独立快照。

分块保留全局坐标及原来的 X／Y 缩放除法顺序，防止非整数缩放的采样相位发生变化。Worker 直接传回合成器的 RGBA，再经主线程的小画布混合；不增加一次透明 ImageBitmap 的预乘通道舍入。生成的半透明 Canvas 素材按主线程原绘图器的读法取得 RGBA 后移交，每约 3 ms 让出；避免不同 Canvas 后端的通道舍入差。这些像素替代 Worker 中对应的素材副本，不同时保留两份。小图保留原生图块／概览采样；缺少后台 Canvas 或后台失败时清空并回退原同步渲染。完整版的原生图片继续走原绘制路径。

这项改动主要减少连续阻塞，未减少导出的分辨率或 JPEG 质量。全图画布的分配、区域／概率图层及编码仍需时间，不能表述成导出全程零阻塞或总时间一定下降。`verify-image-export-async.cjs` 对照图层透明度、区域、无地形格／镜头遮罩、隐藏场景、回退、异常清理及数据隔离；`verify-toy-raster-ui.cjs` 的 38 项像素对照包含非整数全局相位、输出分块与独立任务释放。真实大图另比较全部约 9,943 万像素，同步和异步输出逐通道一致。一次独立对照中，素材及图层总绘制约 3.66 s，其中最后同步绘制图层约 66 ms；原同步路径约 3.21 s。墙钟增加来自分块调度，收益为素材合成不再连续占据界面线程。记录见 `output/other-operation-performance/`。

最终无采样导出复测：绘制约 3.56～3.61 s，主线程长任务峰值约 96～97 ms，16 ms 心跳的最大间隔约 112～117 ms；JPEG 编码另约 1.35～1.65 s。两种概率图层开关下的 JPEG 字节大小也与原路径相同。未把剩余约 0.1 s 峰值称为完全无阻塞。

### 回到前台的首次拖动（2026-11-10）

完整版和 Toy 共用 `interaction-priority.js`。离开页面至少一秒后，通过窗口焦点、页面可见性、`resume`／`pageshow` 恢复事件进入一次短暂保护；重复事件不会重复启动。已完成的场景和概率缓存继续保留，不清空、重算或重新解码原始地图素材。

预热只使用一个常驻 64×64 临时画布，每帧触碰一份已经存在的当前画面、视口场景、区域／数字或 Buff 缓存资源。没有全图重新绘制或像素读回；一旦收到首次平移／缩放输入或发现待处理输入，剩余预热取消或让路。恢复后的安静保护约 180 ms，首次拖动的保护最多 350 ms；长按或持续拖动不会无限推迟后台任务。

共享栅格细化／预览队列在保护期等待一次；区域统计、缩略图、单位 Buff 分片和全格 Buff 打包／发布同样让路。Buff 协调 Worker 在片段边界暂停数值与图层工作，辅助 Worker 完成当前批次后不再派发下一批或提交结果，恢复后继续，不丢掉有效模型和缓存。过期目标仍由原有代际检查拒绝，暂停不是新建一条逐项执行的任务队列。

验证包括 `verify-interaction-priority.cjs` 的重复恢复、每帧单资源、输入取消、保护上限和栅格过期请求；`verify-buff-kernel-pool.cjs` 覆盖辅助线程派发／发布等待和等待期间取消。Full／Toy 的 5,572 项布局仍与原算法 17,982 个正值格逐格对照，最大绝对误差约 `1.25e-14`；半径替换、缓存平台期和实际放置／撤销均通过。

`verify-interaction-priority-ui.cjs` 使用本机 Chrome 156、1900×1300、1.5 倍 DPI 和 130952 大地图，分别关闭／开启恢复策略，测试箱子与 Buff 视图。压力条件是在首次输入时排入 12 个各约 4 ms 的可延后栅格任务，模拟恢复后的后台积压；每个条件取三次中位数。正常无积压条件还用于区分普通帧调度波动。像素对照读私有副本，两组都不对可见画布调用 `getImageData`，避免 Chrome 的读回启发式改变加速路径。

### 提交前复核（2026-11-10）

Toy 栅格任务在素材准备完成、图块／缩略图响应返回和导出分块之间重新检查所属布局的代际，防止旧 Promise 刚完成时切换布局，随后将旧请求发往新 Worker。旧 Worker 的迟到错误不再关闭新 Worker；未发布的旧 ImageBitmap 立即释放，发送失败的请求也从等待表移除。`verify-toy-raster-lifecycle.cjs` 固定复现准备完成和图块完成这两个交错时序，并检查后续绘制仍正常。

Buff 打包／发布的异步让出点在调度前、任务恢复后均检查首次交互优先级，覆盖任务已排入后台但用户输入随后到来的情况。`verify-buff-precompute.cjs` 检查这段期间不会派发数值任务，保护结束后仍能完成。历史测试同步到当前规则：三种模拟单位、停用动员兵放置但兼容旧方案导入、各单位自身海陆通行规则、异步填充与不可选区域取色行为。

复核通过 92 组核心回归脚本、186 个 JavaScript 文件及 40 个 Python 文件的语法检查；浏览器覆盖两版侧栏／切图、密集方案、前台恢复，以及 Toy 的 38 项异步绘制像素对照。外观基准重新生成后，12,372 组组件状态和 33,138 组原版状态通过；278 个原生布局与 294 份 Toy 报告的概率、格子、禁行及有序来源一致。密集方案的 17,982 个 Buff 正值格对照原算法，最大绝对误差约 `1.25e-14`。

本地目录测试须使用与当前资源指纹一致的报告。旧报告的资源变化拒绝是预期保护，不能修改指纹绕过；本轮用当前目录重新生成独立报告，未修改用户资源设置。侧栏／前台恢复脚本支持 `SIM_RESULT` 指定该报告；自动入口接受 `/output/<目录名>/result.json`。测试输出保留在忽略目录，未生成或上传 Release。
